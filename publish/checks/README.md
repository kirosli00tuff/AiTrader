# publish/checks: history scanners for Stage P.1

`scan_history.py` scans a built git repository for the A3, C4 and D6 checks. It uses the Python 3.12 standard library only. Every subcommand reads every object reachable from all refs (`git rev-list --objects --all`, then `git cat-file`). It writes a JSON report to `--out` and prints a short count summary. Values that look secret are masked in the report and on screen. A masked value keeps at most its first 6 characters, plus its length, for example `ghp_aq***[len=40]`.

Run each subcommand like this:

```
.venv-eval/bin/python -I publish/checks/scan_history.py <subcommand> --repo <repo> --out <report.json> [options]
```

Common options: `--max-scan-mb 64` (larger blobs are listed under `incomplete` and are not content-scanned), `--min-free-mb 2000` (the scan stops with exit code 3 when free memory falls below this), `--max-commits-per-location 0` (0 lists every commit), `--fail-on-findings` (exit 1 when there are findings). Exit code 2 means the scan failed. A report is written in every case, with `status` set to `ok`, `error` or `aborted_low_memory`. The process lowers its own priority to nice 10.

Every report has `params`, `stats`, `summary`, `findings`, `low_tier` and `incomplete`. A blob finding carries `blob`, `path`, `line`, `first_commit` and `locations`. `locations` lists every path that holds the blob and every commit whose tree holds it. A commit or tag finding carries `commit` or `tag` and `field` (`message`, `author`, `committer` or `tagger`). Identities are read from the raw objects, so no mailmap is applied. `low_tier` holds hits that need a look but are probably benign: hash-context hex values, bare street words and small JSON files. Read it before ruling, but it does not count toward `n_findings`.

## headlines (A3, C4)

`headlines --headlines-csv <csv> --column headline --min-len 40` loads the headline column. Headlines shorter than `--min-len` are skipped and counted. It then checks every text blob and every commit and tag message for any substring of 40 or more characters of any headline. It checks twice. The exact pass compares raw text. The normalized pass case-folds, collapses whitespace and folds curly quotes and long dashes. It builds a set of every 40-character window of every headline. It probes the text every 20 characters against the 20-character windows, then confirms each candidate against the 40-character set, so no match is missed. A normalized hit on the same line as an exact hit for the same headline is not repeated. Each hit gives the headline row numbers in the CSV (and `--id-column` values when that column exists), the match length and the line. The report holds no headline text unless you pass `--include-text`. Leaving it out keeps the report safe to store next to published files.

## hygiene (C4)

`hygiene --never-list <EXCLUDE-style file> --max-blob-mb 5` checks four things. (1) Paths. Every path in every commit tree is matched against the never list with git-filter-repo `--paths-from-file` rules. A line can be a literal path or directory prefix, `glob:` (fnmatch, where `*` also matches `/`), or `regex:` (Python `re.search` on the path). Lines starting with `#` are comments. Rename lines (`==>`) are ignored and reported as warnings. The tree walk covers the same paths as `git log --all -m --name-only`, and the self-test checks that. (2) Blobs over the size limit (decimal MB). (3) `kiros1134` (and any `--extra-term`) in blobs, commit and tag messages, and author, committer and tagger lines. (4) Phone numbers and street addresses. North American numbers count when formatted: `(415) 555-0134`, `415-555-0134`, `415.555.0134` or `+1 ...`. International numbers need a leading `+` and 8 to 15 digits. Bare 10-digit runs and space-separated groups count only on a line that says phone, tel, mobile, cell, fax, sms, whatsapp or contact. Matches glued to letters, digits, dots or dashes are skipped, which rules out hashes, git ids, version strings and long digit runs. Date-shaped and dot-only international matches are also skipped. Addresses count as structured hits: a house number before a street word (`1234 Maple Street`), `Suite` or `Apt` with a number, a ZIP code after `, <state code>`, and a Canadian postal code after a province. Bare street words (Street, St., Avenue, Road, Drive, Blvd, Lane, Suite, Apt) go to `low_tier`. Each hit has the commit, path, line number and a 60-character context with every hit on the line masked. Use `--strip-depth N` to also match paths with their first N parts removed.

## secrets (D6)

`secrets` scans all blobs and all commit and tag messages and identities. It looks for: Solana keypairs (a JSON file that parses as 64 integers from 0 to 255, any inline array of exactly 64 such integers, and base58 strings of 86 to 88 characters); EVM private keys (64 hex characters with or without `0x`); API keys and tokens by prefix (`sk-`, `sk-ant-`, `ghp_`, `gho_`, `ghs_`, `ghu_`, `ghr_`, `github_pat_`, `xox[abprs]-`, `AKIA`, `ASIA`, `AIza`, `hf_`, `pk_live`, `sk_live`, `rk_live` and their `_test` forms, `glpat-`, `ya29.`, `npm_`, `pypi-`, Telegram bot tokens, Alpaca key ids, Slack webhooks); `Bearer` headers; PEM private key blocks and PuTTY key files; email addresses; and account ids. Account ids are a value of 8 or more letters and digits, with at least one digit, after a word like account, acct, account_id, wallet, address, pubkey or public key. They also include base58 strings of 32 to 44 characters and `0x` plus 40 hex characters. A 64-hex value on a line that names sha, sha256, hash, digest, commit, manifest, checksum, tree, parent, object, oid, blob, ref or tx, or a `sha256sum` style line, goes to `low_tier` as `excluded`. That only happens when the line does not also say private, secret, seed, mnemonic, signing, keypair or wallet. Base58 checks skip pure hex (git ids, md5) and runs inside long base64 data. Allowed emails are `*@users.noreply.github.com`, `noreply@anthropic.com`, emails on `Co-authored-by:` lines that name a model, and anything passed with `--allow-email` (an address or `@domain`). Other emails are reported with `email_domain`. The flag `generic` marks example and test domains and `git@github.com`. Gzip and zip blobs are opened one level deep, and hits inside them carry `member`.

## paths (D6)

`paths --exclude-file <archive EXCLUDE.txt> --max-blob-mb 5` matches every path in every commit against the archive exclusions. It uses the same rule syntax as `hygiene`. It also lists every blob over the size limit and every blob that parses as a JSON array of 64 integers, or holds such an array inline. The research archive imports each source under `<group>/<name>/`. Pass `--strip-depth 2` there so a rule such as `data/` also matches `<group>/<name>/data/...`. A finding says whether it matched on the `full` or the `stripped` path.

## bulktext (D6)

`bulktext` looks for third-party text in bulk. It reports: CSV, TSV and sniffed delimited files whose header has a column named headline, title, summary, body, text, snippet, article, content or description, or a name built from those words such as `news_headline` (`bulk_text_table`); JSON and JSONL files with objects that hold such a key with a string value (`bulk_text_json`); tables and JSON with three or more market-data columns such as open, high, low, close, volume, bid, ask or price (`market_data_table`, `market_data_json`); text files over 50 lines where 10 or more lines carry a date plus a news outlet name or news site URL on the same or a nearby line (`news_like_text`); HTML and MHTML pages (`html_page`, with saved-page markers such as `saved from url`, SingleFile, `og:` meta or an external canonical link); and PDF files. Text findings give row or item counts and prose statistics: average length, and the share of values with 5 or more words. Findings under `--bulk-min-items 10`, and HTML pages with no saved-page marker, go to `low_tier` as `minor`.

## Self-test

`test_scan_history.py` builds a small synthetic repo in a temporary directory. It plants made-up keys, a 64-integer keypair file that a later commit deletes, a token in a commit message, a personal author email, fake phone numbers and addresses, headline quotes, a 5.6 MB blob, a saved HTML page and bulk CSV and JSONL files. It checks that each subcommand finds every plant and maps it to the right commits. It checks that sha256 lines, git ids, noreply addresses, timestamps, version strings and long digit runs are not flagged. It also checks that no planted value appears unmasked in a report or on screen. The planted values are generated at run time, so this file holds no key-shaped text.

```
PYTHONPYCACHEPREFIX=$HOME/.cache/news_eval_pyc .venv-eval/bin/python -m pytest -q -p no:cacheprovider publish/checks/test_scan_history.py
```

## Limits

Blobs over `--max-scan-mb` are listed, not read. Compressed formats other than gzip and zip (7z, xz, bz2, zip inside zip) are scanned only as raw bytes. A gzipped tar is decompressed once and its stream scanned as one member. Encrypted zip members are listed under `incomplete`. Reflog-only objects are not scanned, because they are not pushed. Unformatted 10-digit phone numbers are found only on lines that say phone or a similar word. An email whose top-level domain is also a file extension (png, py, md, js, zip and similar) is treated as a file name and skipped.
