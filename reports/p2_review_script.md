## 1. Findings

### SF-1. SHOULD FIX. The script does not clear GIT_DIR, GIT_WORK_TREE or GIT_INDEX_FILE, so an exported GIT_DIR makes its own git commands act on the wrong repository. go_public.sh:57 (set -euo pipefail; no unset follows), 274 to 279 (build_profile's `git init`, `add`, `commit`), 244 to 258 (plan_append's fetch, read-tree, commit). The harness strips these for itself at test_go_public.sh:69 and so never exercises the script with them set.

Trace. With GIT_DIR set, `git init -q -b main "$dir"` (line 274) re-initialises $GIT_DIR instead of $dir, and `git -C "$dir" add` / `commit` stage the build folder into that repository's index and commit on its HEAD. The builders at lines 288 and 302 inherit the same environment.

Evidence. Script run in the kept scenario s01 with `GIT_DIR=<stand-in AiTrader>/.git`, `--dry-run`, stub gh, GIT_ALLOW_PROTOCOL=file (output in /home/kiros-li/.cache/p2-tmp/ScriptReviewer/gitdir_dryrun.out). The stand-in AiTrader's HEAD moved from ac4540f to 4796ec9 ("archive rebuilt", a commit written by the stub builder), tracked files went from 8 to 3, the script's own build_profile printed `warning: re-init: ignored --initial-branch=main`, and the run died at exit 128 with `fatal: path 'publish/profile/README.md' exists on disk, but not in 'HEAD'`. The three bare remotes were untouched (54e078a b548a89 d54e472 before and after).

Blast radius. GitHub is protected: step 3's plan read `rev-parse main` from the wrong repository, found it was not a fast-forward of llm-news-drift's main and stopped (line 220), which in a real run is `die` before any push; and a plain push of a diverged branch is refused by git anyway (section 2, E1). The damage is to the local AiTrader checkout (HEAD and index rewritten, recoverable from the reflog), and it happens in `--dry-run` too, before any gate that could notice. This needs GIT_DIR exported in the shell that runs the script, which is unusual for a hand-run in tmux, so SHOULD FIX rather than BLOCKING.

Fix. After line 57: `unset GIT_DIR GIT_WORK_TREE GIT_INDEX_FILE GIT_OBJECT_DIRECTORY GIT_ALTERNATE_OBJECT_DIRECTORIES GIT_COMMON_DIR GIT_NAMESPACE`. Do not unset GIT_CONFIG_COUNT or GIT_CONFIG_PARAMETERS: the harness's URL redirect (test_go_public.sh:275 to 276) depends on them, and the harness already unsets the three named variables for itself, so the change leaves every scenario as it is.

### SF-2. SHOULD FIX. Three gate checks read a tool error as "clean". go_public.sh:113 (`hits="$(grep -rnF ... || true)"`), 148 (`if [[ -n "$(git -C "$aitrader" status --porcelain -- publish/)" ]]`), 155 (`if git -C "$aitrader" grep -qF -e "$MARK" HEAD -- ...`). All three are inherited from the baseline (e5c1810 lines 67, 92, 98; the diff only turned `die` into `stop`), so this is not a regression, but the direction is unsafe: a failing check passes.

Trace and evidence. `grep -r` exits 1 for no match and 2 for an error; `|| true` makes both `hits=""` and line 119 prints "no confirm marks". Reproduced: a directory with an unreadable subfolder gives grep status 2 and `hits=''`. `git grep -q` exits 1 for no match and 128 for an error (a bad ref), and the `if` treats both as "no marks" (reproduced: 1 and 128). A failing `git status` at line 148 yields "" and the uncommitted check passes vacuously. In Kiros's own checkout these errors are unlikely (every file under publish/ is readable and HEAD resolves), which is why this is SHOULD FIX, not BLOCKING.

Fix. Capture the status and stop on anything other than 0 or 1, for example `hits="$(grep ... )"; rc=$?; (( rc <= 1 )) || stop "step 1: grep failed ($rc)"`, and `git grep ...; case $? in 0) stop ...;; 1) ;; *) stop "HEAD check failed";; esac`, and `status="$(git status ...)" || stop "git status failed"`.

### N-1. NOTE. Bare ref name `main` and a tail-matched ls-remote pattern. go_public.sh:190 (`ls-remote ... refs/heads/main | awk '{ print $1 }'`), 197, 202, 259, 401, 408 (`main`, `main:main`).

`git ls-remote <url> refs/heads/main` matches the tail of a ref name: reproduced that a branch literally named `refs/heads/refs/heads/main` prints a second line, so `old` would hold two ids. Consequence is fail-safe: `[[ "$old" == "$new" ]]` is false, `cat-file -e` on the two-line value fails, the news and public paths stop, and the private path would hand git a malformed lease. `git rev-parse main` resolves a tag named `main` ahead of the branch (reproduced: with both present, `main` gave the tag's id and git warned "refname 'main' is ambiguous"). The builders are in-repo scripts that create neither, so this is robustness only. Suggest `awk '$2 == "refs/heads/main" { print $1 }'` and `refs/heads/main` in rev-parse, merge-base and the refspec source.

### N-2. NOTE. The force path's window. go_public.sh:404 to 408. The second visibility read and the force-push are two calls; a flip to public between them is not seen. `--force-with-lease=refs/heads/main:$old` still refuses to overwrite anything pushed in that window (reproduced: a stale lease is rejected with "stale info"), so the only unprotected case is a flip with no new push, which rewrites history that was private when read a moment earlier. Inherent to the design; no cheaper guard exists in gh.

### N-3. NOTE. A late stop leaves earlier repos pushed. go_public.sh:402, 406, 409. Only a failed push or the force re-check can stop after the first push; the messages say so ("Repos listed before it in the plan were pushed"), and a rerun plans "nothing to push" for them. Matches the author's note 3. Acceptable.

### N-4. NOTE. The public append path replaces the whole tracked tree. go_public.sh:244 to 245. Anything added to a public repo outside the build (a LICENSE added on the website, for instance) is deleted at the next update. This is what Part B asks for; the `diff --cached --stat` in the plan (line 345) is the only warning, so it must be read before "go public" is typed.

## 2. Primitive evidence (my sandbox, /usr/bin/git 2.53.0, file:// remotes, no hooks)

- E1. A plain `git push <url> main:main` of a diverged branch is rejected: `! [rejected] main -> main (fetch first)`, exit 1, remote unchanged. This is the form the script uses for every `push` and `append` plan (line 401), so neither can rewrite history even if the script's own fast-forward test were wrong.
- E2. `git push --force-with-lease=refs/heads/main:<stale id> <url> main:main` is rejected: `! [rejected] main -> main (stale info)`, exit 1, remote unchanged. This is the force form (line 408).
- E3. `git read-tree -u --reset FETCH_HEAD` leaves the index and work tree equal to the fetched tree, with `drop | 1 -` in `diff --cached --stat` (line 245's mechanism).
- E4. `git ls-remote` on an existing repo with no main: exit 0, empty output (the "empty main" case, line 230). On a missing repo with pipefail: exit 128 (the "failed" case, line 226). The script distinguishes the two correctly.
