## 1. Definitions implemented in verify.py (from the pre-registration only)

- Day exclusion (9.1, Task 7 line 2411): per collection `query_date`, share =
  rows with state = source_failed over all run_kind = 'collection' rows of
  that query_date; excluded when share > 0.20 (strict).
- S* (9.7): sessions = distinct non-empty scoring_session among judged
  collection rows; a pending judged row is stale when index(latest resolved
  session) minus index(its session) > 3; S* = the session before the
  earliest non-stale pending session, or the latest session when none.
- Scorable (9.7): run_kind collection, state judged, judgment in (POSITIVE,
  NEGATIVE), outcome_state resolved, exclusion_reason '', scoring_session
  non-empty, query_date not excluded, scoring_session <= S*, excess_1session
  not NULL (NULL rows counted and excluded, never 0).
- G (9.8): the same without the judgment condition.
- T (9.4): sum of signed_bp over observations / n; signed_bp = +/-10,000 x
  excess_1session by judgment.
- Bootstrap (9.5): 10,000 draws, C clusters with replacement (multinomial
  counts), T* = ratio with multiplicity, SE = std ddof 1, z = T/SE, interval
  T +/- 2.50 SE.
- Permutation (Amendment 6, 9.3, 9.9): within each scoring_session, labels
  reassigned uniformly without replacement over the test's observations,
  10,000 draws, p = min(1, 2 x min(1+ge, 1+le)/10,001), upper tail = ge < le.
- Minority share = min(P, N)/(P+N) over scored observations; mixed clusters =
  scoring_session clusters with at least one POSITIVE and one NEGATIVE.
- Gate (9.8): sigma = std ddof 1 of 10,000 x excess over G; one-way ANOVA ICC
  with n0 = (N - sum n_c^2/N)/(C_G - 1), rho = (MSB - MSW)/(MSB + (n0-1) MSW)
  floored at 0; k_eff = sum m_c^2 / M over directional scorable rows;
  Required = 11.156 x (sigma/30)^2 x (1 + (k_eff-1) rho); pass when C_dir >=
  60, M >= 1,000, M >= Required.

Seeds: mine boot 7001, perm 7002 (any seed allowed by the brief); the
harness uses 9.11's BOOT_SEED 20261010 / PERM_SEED 20261011 child 0 for
(P1, primary). The stochastic quantities are therefore compared within Monte

- SE: 4 Monte Carlo standard errors of a bootstrap SD estimate,

  (B+1). Observed count differences were 0, 14 and 3 against tolerances of

### NOTE 1. S* staleness counts data sessions, not exchange sessions (conservative)

news_eval/cutoff.py:171-186 orders `sessions = tuple(sorted(placed))`, the
distinct scoring_session values holding judged collection rows, and calls a
pending row stale when `index[latest_resolved] - index[s] > 3`.
EXPERIMENT.md line 917-919: "A pending row whose `scoring_session` is more
than 3 sessions before the latest resolved session is reported as stale and
does not hold S* back." Mapping D16 fixes "sessions" as the data's session
list. A trading session with no judged row at all (a whole day model_failed
or source_failed; "gaps stay gaps") is absent from that list, so the index
gap undercounts the calendar gap and a row the calendar reading would call
stale can hold S* back. Direction: S* earlier, analysis set smaller, never
larger; no outcome leakage. Concrete input: sessions with judged rows
2026-10-01, 10-02, 10-06, 10-07, 10-08 (10-05 absent), one pending row on
10-01, latest resolved 10-08: calendar gap 5 sessions (stale), list gap 4
(stale), fine; but with 10-05 AND 10-02 absent, list gap 3, not stale, S*
= none before 10-01, and the set loses 10-01 to 10-08. Lead decision (D16 is
the lead's); no code change proposed by me.

### NOTE 2. S* is computed over all judged collection rows, including rows on 9.1-excluded days (conservative)

news_eval/data.py:576-585 `judged_session_status` has no query_date filter;
cutoff.compute_s_star uses it. EXPERIMENT.md line 915-917 reads literally
"the latest `scoring_session` at or before which no judged collection row is
still `pending` in the snapshot", so the harness follows the text. Line
848-850 (9.1) says excluded-day rows "leave the analysis set before clusters
form", which could be read as excluding them from the S* scan too. A pending
row on an excluded query_date can therefore pull S* back although it would
never be scored. Direction: smaller set, never larger. On the three
scenarios the excluded day 2026-08-25 held no pending row, so no effect.
